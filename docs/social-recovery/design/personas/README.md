# Personas

The named users the ux chapter answers to, one file per persona under a stable id, written for the partner's engineer and for the fresh verifier who replays a journey against the design. This directory is the persona register the engine reads on this instance, so a future `persona-replay` invariant names a file here by path. Until the engine's mixed-dialect work lands, the ux chapter's invariants bind `human-only` and the replays run as attack lenses, one fresh seat per persona, recorded in the round that ran them.

Each file carries one persona under an id minted once and never reused, `P-1-sam.md`. A persona is a fixture and never a real person: no live address, mailbox, document number or secret, because the file ships to every fresh verifier and travels wherever the instance travels. The body states who the person is, their technical level, what they hold that the design touches, what they stand to lose, then their journeys through the design as short narratives, each naming the screens it traverses by the codes the wireframes carry. A journey sentence is a design claim with the standing an invariant statement has, so "she skips the wizard" binds the design.

The five holders came in with the imported Kohaku work, where the owner approved them against the persona research, and each was remapped from the dropped email method to zkPassport there; the sixth file, `P-6-sara.md`, is the guardian fixture the ux chapter's first attack round added, the person on the other end of a guardian row. Here they enter as material to validate: the owner approves every file the way D-0 is approved, in the round that opens the chapter, and a persona that changes after approval re-enters as that stage with every journey that leaned on it re-judged.
